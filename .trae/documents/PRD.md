# 个人主页占位页 PRD

## 1. 项目背景与目标

### 1.1 背景
- 域名：`Lin23-071.github.io`（GitHub Pages）
- 用途：求职简历上挂的个人主页链接
- 现状：旧版本已存档，新主页正在筹备

### 1.2 目标
在主页"还没准备好"的过渡期，提供一个：
1. **有信息量**的占位页——告诉访客"这里正在装修，不是 404"
2. **有趣味性**的占位页——访客可以玩个 Chrome 断网小恐龙游戏打发时间
3. **有审美主张**的占位页——能体现主人的设计品味，作为简历背书

### 1.3 非目标
- 不是完整的主页（相册、技能树、项目展示等以后再加）
- 不接入后端 API、不收集数据
- 不引入第三方 npm 包（保持轻量、可离线运行）

## 2. 用户场景

### 2.1 主场景：HR / 面试官点开链接
- 路径：收到简历 → 点开主页链接 → 看到"正在装修中" → 不会觉得是死链 → 可能玩一下小恐龙 → 关掉页面
- 期望：觉得"这人有意思""审美在线"，对后续面试加印象分

### 2.2 次要场景：朋友/同学偶尔看一眼
- 路径：随手打开看看 → 玩两把游戏 → 走
- 期望：好玩，能截图分享

### 2.3 边缘场景
- 移动端访问：需可读、可点开游戏
- 离线访问：游戏不依赖网络

## 3. 设计方向

### 3.1 一句话风格
> **"建筑工地的施工告示牌，被一本独立杂志的设计师重新排版过。"**

把"正在装修"这件事当主角来设计，而不是藏着掖着。

### 3.2 调性关键词
- 有趣、幽默、不端着
- 大方、留白足、不拥挤
- 有质感（颗粒、纸感、印刷感）
- 一眼能记住（"这主页有恐龙游戏"）

### 3.3 色彩（避免紫白渐变、AI 默认配色）
| 角色 | 色值 | 说明 |
|---|---|---|
| 背景 | `#F4EFE6` | 奶油米白，温暖不刺眼 |
| 主文字 | `#1A1A1A` | 墨黑，标题与正文 |
| 副文字 | `#6B6557` | 灰咖，弱化层级 |
| 警示黄 | `#F5C518` | 施工带，活泼但调低饱和度 |
| 柿红 | `#D65A3C` | 印章、按钮、点睛 |
| 苔绿 | `#6B7A4A` | 装饰、呼应主人旧作 |
| 描线 | `#1A1A1A` | 1.5–2px 实线 |

### 3.4 字体（明确避免 Inter、Space Grotesk、Roboto）
| 角色 | 字体 | 来源 |
|---|---|---|
| 主标题（英文） | **Fraunces** | Google Fonts，可变字体，光学尺寸变化 |
| 主标题（中文） | **Noto Serif SC** | Google Fonts，与 Fraunces 呼应 |
| 副标/装饰 | **JetBrains Mono** | Google Fonts，打字机感、geek 感 |
| 装饰斜体 | **Caveat** | Google Fonts，手写体，便签用 |

### 3.5 核心装饰元素
1. **施工带**：黄黑斜纹条带，贯穿 hero 区，暗示"正在施工"
2. **手撕便签**：几个错位漂浮的便签纸，写着"装修中别急""新版本在路上""欢迎常来"
3. **卷尺**：边缘放一根 SVG 卷尺，标尺刻度
4. **印章**：右下角一个圆形红章"UNDER CONSTRUCTION"
5. **Risograph 颗粒**：全局叠加一个非常微弱的噪点纹理

## 5. 交互细节

### 5.1 加载入场（页面打开 0–1.6s）
- 0.0s：背景淡入
- 0.2s：施工带从左滑入
- 0.4s：Hero 大标题逐字出现（打字机效果，每字 60ms）
- 1.0s：副标英文开始打字
- 1.2s：游戏邀请卡片淡入
- 1.4s：便签依次从不同方向"飘入"
- 1.6s：印章盖下（缩放 + 旋转动画）

### 5.2 鼠标交互
- 便签轻微跟随鼠标做 3D 倾斜（max 6°）
- 主按钮 hover：背景填充动画
- 装饰元素 hover：轻微抖动

### 5.3 游戏交互
- 点击"开始游戏"按钮 → 卡片展开成游戏区（高度 0 → 400px 动画）
- 空格 / 点击 / 触屏：恐龙跳跃
- 下箭头 / 双击：下蹲（可选，简化版可去掉）
- 碰撞：游戏结束，弹出"再来一把？"
- 计分：屏幕右上角

### 5.4 隐藏彩蛋
- 输入 "071" 任意位置（键入不连续也行）：触发一个"特殊彩蛋"
- 点击 Hero 标题文字三次：标题文字变成手写体 0.5s
- 按 R 键：游戏重开

## 6. T-Rex 小游戏规格

### 6.1 玩法
- 横版跑酷
- 恐龙自动向右跑（视觉上背景向左滚）
- 障碍物：随机生成仙人掌（高度 30/50/70px，间距 400–900px 随机）
- 操作：空格 / 触屏点击 → 跳跃；长按空格 / 长按 → 长跳（高级）
- 计分：每帧 +1，每 100 分速度提升一档
- 死亡：撞到障碍物 → 显示"再来一把" + 最高分

### 6.2 视觉风格
- 白天模式：白底 + 黑线条
- 恐龙：仿 Google 风格的简笔几何（矩形身体 + 头 + 后腿）
- 仙人掌：黑色实心剪影
- 地面：底部一条线 + 等距竖线纹理

### 6.3 技术实现
- 单文件 React 组件 `TrexGame.tsx`
- 用 `<canvas>` 渲染
- 自实现物理（重力、跳跃）
- 不依赖任何第三方包
- requestAnimationFrame 驱动
- 适配 DPI：高 DPI 屏幕用 devicePixelRatio 缩放

### 6.4 难度
- 起步速度：6 px/frame
- 每 100 分：速度 +1
- 上限速度：18 px/frame
- 跳跃初速度：-15 px/frame，重力 0.6 px/frame²

## 8. 性能与可访问性

### 8.1 性能
- 首屏 JS：< 100KB gzipped
- 字体：仅引入需要的字重，subset 化
- 图片：无（全是 SVG / CSS）
- Canvas 游戏：60fps 目标
- 噪点纹理：单张 200×200 PNG 重复平铺（base64 内嵌，避免额外请求）

### 8.2 可访问性
- 所有按钮有 `aria-label`
- 颜色对比度 ≥ 4.5:1（已检查）
- 支持键盘操作（Tab / Space / Enter）
- 尊重 `prefers-reduced-motion`：关闭入场动画与漂浮动画
- 游戏区有"开始游戏"文字按钮，不强制依赖视觉

### 8.3 浏览器兼容
- Chrome / Edge / Safari / Firefox 最新两个大版本
- 移动端 Safari / Chrome
- 不支持 IE
